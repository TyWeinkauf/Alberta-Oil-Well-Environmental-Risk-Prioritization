# Limitations and responsible use

- All demonstrated screening results currently use project-authored synthetic records. Real AER wells, provincial water/parks and federal critical habitat remain the intended inputs; no official analytical or production records have been loaded. Proximity is not contamination likelihood or an operational environmental-risk determination.
- HTTP downloads, ArcGIS, local GIS/GeoJSON, coordinate-mapped well CSV and production CSV/ZIP are implemented. Official source-specific schemas, actual CRS, coverage, dates, permitted use remain unverified. Regional preparation now handles direct local originals, but actual full ST37 archive behavior/performance is untested. Petrinex and monthly production are now outside the current scope. A Drayton Valley pilot is configured; its actual source coverage is not established.
- Cloud HTTP failures describe specific requests in this environment. The user's runtime may reach publisher APIs/downloads or use separately downloaded files. Discovery permissions now work for several catalogue/public pages; actual service/download access still differs by host. See [discovery evidence](source_discovery.md) and [runtime input routes](data_access.md).
- Distances use actual geometry in EPSG:3400 and a 500 m environmental margin. Invalid geometries are quarantined rather than silently repaired. Incomplete/unavailable coverage means unknown, not a known absence. The synthetic protected-area demo is incomplete because its invalid polygon was quarantined. Known-distance tests do not establish positional accuracy or completeness of official inputs.
- Retained optional legacy production charts require exact, unique, documented well identifiers. The default catalogue/UI excludes this workflow; no production source is required. Facility, ambiguous, unmatched, masked and unknown records do not become well-level production. Products/activities/units remain separate, missing months are not zero, and licensee/operator/producer are distinct roles. Actual Petrinex masking, units, record identity, terms and historical attribution still need source-specific implementation/validation.
- A database-wide advisory lock permits one application mutation workflow at a time, across processes; read-only results remain accessible. It reserves one pooled database connection in addition to working connections (default SQLAlchemy pools suffice; a single-connection pool is unsupported). PostgreSQL releases the lock when its session ends. Previously abandoned attempts are marked interrupted by the next cooperating mutation. Stop old application versions before upgrading so unguarded old processes cannot run alongside this coordination model.
- PostGIS is authoritative. Files and database commits are not a distributed transaction: unreferenced artifacts after interruption do not prove a successful run. Rerun the same inputs to verify counts and regenerate reports; corruption fails closed rather than silently replacing immutable inputs. See [recovery instructions](release_verification.md).
- The measured benchmark is 1,000 synthetic wells and 30 features on this Linux environment. It establishes a bounded local baseline, not Alberta-wide throughput, memory capacity, production concurrency or a performance guarantee. Query/loading performance with real geometry volumes remains to be measured.
- Isolated candidate-checkout verification used a new Python virtual environment, local cached dependency wheels and a new PostgreSQL database. Full Python tests and offline Chromium checks passed. It does not establish OS/PostgreSQL installation on a new machine, Windows execution, live-source compatibility or the exact eventual published release commit.
- Keep downloaded inputs, private catalogues, credentials and generated outputs outside Git. This is local development software; PostgreSQL deployment, backups, permissions and access controls belong to the eventual runtime configuration.
- Separate course evidence indexes are being prepared. Actual-data interpretation, final screenshots/results and submission requirements remain open. Existing assignment documents are preserved; current instructor/D2L requirements determine the graded handoff. The application follows the user-selected Streamlit/OpenStreetMap design without QGIS.

- Regional preparation bounds selected rows/fields and output packages, without a second province-wide cache copy. It still requires the original local download and streamed hashes before/after preparation; GDAL may scan/decompress substantial data. A complex single geometry can consume significant memory. Provider spatial filtering may omit null/invalid original geometry, so extract counts do not constitute a province-wide quality audit. Prepared data is bound to its study configuration; create a new extract when that configuration changes.
